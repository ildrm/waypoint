# Effort and WBS model

Owner: R28. Reviewers: R04, R19, R27. Status: proposed documentation, 2026-10-29; no human approval.
Sources: [authorized brief](../00-governance/sources/documentation-super-mega-prompt.md) and user clarification (14 named languages; free use; no platform payments). Related IDs: OUT-EFFORT, AC-04, AC-05. Open decisions: [register](../00-governance/assumptions-and-open-questions.md). Practice: [estimation-commercial](../00-governance/skills/estimation-commercial.md).

Decompose discovery, UX/UI, content/localization, foundation, incremental platform features, integrations, migration, quality/security, release and handover. Each work package records feature IDs, quantity, role hours low/base/high, dependencies, acceptance complexity, source and assumptions.

A shared identity/API/data foundation is counted once for web+Android+iOS; each surface adds interface/device/offline behavior and platform-specific QA. CMS configuration and custom build alternatives have separate WBS, not a flat multiplier for all projects. Unknown integration documents create a discovery package and unresolved delivery range. Translation effort depends on source words/locales/review/visual QA; locale count is not a generic price surcharge.

Illustrative C01 role-hour WBS: discovery BA40; design UX40; implementation DEV160; quality QA64; release OPS16. Total 320. Features:12 pages,3 content types,2 editorial roles, one lead route, one language, one deployment. Proposed low/base/high256/320/432 are expert-assumption scenarios (0.8/1/1.35 factors), not confidence intervals or calibration. Factors are for fixture sensitivity only; production estimates decompose uncertain packages rather than multiplying indiscriminately.

Do not charge fixed deliverable and its included hours twice. Excluded content production/customer approvals remain explicit dependencies, not assumed free effort. Collect actual approved timesheets/scope changes later with consent to calibrate error by work type; do not invent empirical coefficients.
